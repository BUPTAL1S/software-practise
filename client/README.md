# client

JavaFX 桌面端，Win / Mac **同一份代码**。阶段 5：REGISTER + 一对一音视频通话 + SIP MESSAGE 文字消息 + 后台 HTTP 文件上传与下载 + 登录对接与 CDR 通话记录统计上报 + FreeSWITCH 房间 MCU 音视频会议。

## 准备

- JDK **17**（`JAVA_HOME` 指向它）
- Maven
- 本机编好的 PJSUA2 2.17 原生库（开启视频支持，见下方）
- Spring Boot 后台服务（用于文件上传/下载、用户鉴权与 CDR 通话记录统计，见 `admin/` 目录）


## 编 JNI（阶段 2/3 音视频与消息底座）

| 系统 | 文档 | 产物（不入库） | 编解码器与视频后端 |
|---|---|---|---|
| macOS arm64 | [native/macos-arm64/BUILD.md](../native/macos-arm64/BUILD.md) | `native/macos-arm64/libpjsua2.dylib` | Cisco OpenH264 + Metal / AVFoundation |
| Windows x64 | [native/windows-x64/BUILD.md](../native/windows-x64/BUILD.md) | `native/windows-x64/pjsua2.dll` | Cisco OpenH264 + DirectShow / SDL2 |

SWIG 生成的 Java 放在 `src/main/java/org/pjsip/pjsua2/`，两平台共用，必须都是 2.17。

### 跨端 H.264 编解码器统一约定

全组音视频统一采用 **H.264** 编解码（SDP 编码名 `H264`，时钟率 90000，Packetization-Mode 1，载荷类型 97）：
1. **macOS**：编译启用 Cisco `openh264`，与 Windows 保持相同的 SDP payload type 97 与 profile-level-id，彻底避免非对称 SDP 协商失败导致自动挂断；
2. **Windows**：依赖 MSYS2 MinGW-w64 提供的 Cisco `openh264`；
3. **Kamailio**：透传 SDP 视频 m-line，不转码，两端直接协商建立 RTP 视频流；
4. **FreeSWITCH MCU**：后续阶段 5 视频会议室统一接收 H.264。

> **阶段 1 纯音频库平滑兼容**：如果使用阶段 1 编译的无视频库启动，客户端主界面会自动检测并显示「阶段 1 纯音频模式」，呼叫与接听自动降级为语音通话，所有 SIP 信令与注册保持完全可用。

## 启动与联调

### 1. 启动支撑服务
在进行阶段 3 完整联调时，建议在开发机启动后台与信令：
```bash
# 启动信令代理 Kamailio
cd server && docker compose up -d

# 启动后台服务（提供 HTTP 文件存储与用户鉴权）
cd admin && mvn spring-boot:run
```

### 2. 启动客户端

在 `client/` 目录：

```bash
# macOS 窗口 1（用户 1001）
./启动.command

# 同机窗口 2（用户 1002，指定端口与对端）
./启动.command --user=1002 --port=5062 --peer=1001
```

```bat
REM Windows 窗口 1（用户 1001）
启动.bat

REM Windows 窗口 2（用户 1002）
启动.bat --user=1002 --port=5062 --peer=1001
```

或直接用 Maven：

```bash
mvn javafx:run
mvn javafx:run -Djavafx.args="--user=1002 --port=5062 --peer=1001"
```

本机 SIP 端口若被占用会自动 +2。不要两个窗口用同一个账号（usrloc 会被后注册的顶掉）。

  - **【⚡ 一键启动并上线】**：自动以异步任务顺序触发引擎启动、SIP 注册与后台静默登录，新手或验收一键就绪；
  - 独立设置窗口入口与直接拨号输入框（支持输入分机号或 `room-<id>`）；

- **主工作区 (Main Workspace)**：
  - **顶部常驻控制栏**：包含标题、实时 H.264 探测与采集设备状态、摄像头预览按钮、视频呼叫、语音呼叫与挂断按钮；来电时顶部滑入醒目的绿色接听横幅；

- **独立网络与账号设置模态弹窗**：
  - 将 SIP 服务器、HTTP 后台、传输协议、SIP 域、用户名、密码与本地端口移入非阻塞设置窗口；
  - 包含「填入本机 IP」、「测试后台」及分步测试按钮，双机联调与改 IP 极其方便，主界面视觉负担减少 40% 以上；
- **CDR 统计指标卡与表格矢量空状态**：
  - 原 4 项统计 Label 封装为 `.metric-card` 悬浮指标卡；
  - CDR 记录与会议房间 TableView 配置原生 `SVGPath` 矢量图标空状态视图。

### 1. 通话与视频
- **启动引擎**：检测本机 SIP 端口、探测 H.264 视频编解码器及摄像头/渲染设备。
- **注册/上线**：输入 SIP 服务器 IP（Kamailio 宿主机校园网 IP，或同机 Docker 填 127.0.0.1），点「注册/上线」。
- **摄像头预览**：可点击「摄像头预览」检查本地画面。在发起呼叫或点击接听时，客户端会自动关闭预览以释放摄像头硬件。
- **视频呼叫 / 语音呼叫**：
  - 点「视频呼叫」发送含音视频媒体（H.264 + PCMU）的 INVITE。
  - 点「语音呼叫」仅协商音频媒体。
- **接听**：收到来电提示时，可选择「接听(视频)」或「接听(语音)」。
- **视频画面呈现**：音视频接通后，底层 PJSUA2 自动弹出独立的低延迟硬件加速原生视频窗口展示远端画面。
- **挂断**：任意一端点击「挂断」，释放呼叫并关闭视频窗口。

### 2. 即时文字消息（阶段 3 新增）
- **发文字**：在右栏输入框输入文字，按 Enter 或点击「发送」。
- **传输链路**：客户端调用 PJSUA2 `Buddy.sendInstantMessage`，发送 Content-Type 为 `text/plain` 的标准 SIP MESSAGE 报文经由 Kamailio 路由到对端。
- **送达回执**：
  - 发出时界面状态标记为「已发送」；
  - 收到 Kamailio / 对端返回的 `SIP/2.0 200 OK` 时，底层触发 `onInstantMessageStatus` 回调；
  - 界面采用 **FIFO 正向精确匹配** 机制（先按报文正文自先往后匹配最早发出的待确认消息，匹配不到再顺序回退最早未确认项），彻底解决连续发送多条相同内容时回执倒置或串条问题，精准标记「已送达」；
  - 若遇网络超时或未上线，将显示「发送未送达(状态码 原因)」。
- **对话切换**：点击历史消息中对方的名字或快捷按钮（`1001` / `1002` / `1003` / `room-101`），即可一键切换当前聊天与呼叫对象。

### 3. 文件上传与共享（阶段 3 新增）
- **发送文件**：
  1. 点击「📎 发文件...」，选择本地任意文件（图片 🖼️、音频 🎵、视频 🎬、压缩包 📦、文档 📄）；
  2. 客户端使用 Java 17 标准 HTTP 客户端发起 `POST /api/files`，携带 `file` 二进制及 `from`、`to` 字段上传到 Spring Boot 后台；
  3. 后台将文件落盘并生成唯一下载索引，返回 `{"id": 1, "name": "...", "size": 1234, "url": "/api/files/1"}`；
  4. 客户端封装轻量元数据 `[FILE] <文件名> | <文件大小> | <HTTP下载URL>`，通过 SIP MESSAGE 发送给对端。**不在 SIP 报文中携带大二进制数据**，确保信令链路轻量稳定。
- **接收与下载文件**：
  1. 接收方收到通知后，自动解析为文件卡片，展示文件类型图标、原文件名与格式化大小；
  2. 点击「下载文件」或「另存为...」，唤起本地路径选择框，通过 HTTP 流式下载到本地；
  3. 下载完成后，卡片提供「打开」按钮直接唤起系统默认程序打开文件；
  4. **窗口内图像实时预览**：发送端发出的图片及接收端下载完成的图片（PNG/JPG/GIF/WebP），卡片内均支持 **直接在 JavaFX 窗口内呈现图片缩略图**，点击缩略图即可原尺寸查看，真正做到「图/语音/短视频，能发能看」。
- **后台 HTTP 连通性测试与鉴权**：
  - 设置区提供「HTTP 后台」地址配置（默认 `http://localhost:8080`，可保存至本地偏好）。
  - 可点击「测试后台」验证后台探活（`GET /api/health`）与密码鉴权（`POST /api/login`）。

### 4. 登录对接与 CDR 通话记录统计（阶段 4 新增）
- **账号与登录鉴权**：
  - **演示账号凭证约定**：Spring Boot 后台内置演示用户（`1001`~`1008`），其 HTTP 密码与用户名完全一致（即 `1001/1001`）；Kamailio SIP 账号支持任意非空密码；
  - **输入框联动与默认填充**：启动时密码框自动填充为与用户名相同（默认 `1001`），修改用户名时若密码未做特殊定制将自动同步跟随；
  - **明确的状态徽标与静默登录反馈**：启动以及 SIP 注册成功后自动执行后台静默登录；成功后显示绿色徽标「已登录 (用户名)」，文件与 CDR 请求自动携带 `Bearer <token>`；若未连后台或静默登录失败，徽标明确置为「未登录」并打印提示日志；手动点击「登录后台」失败明确显示「登录失败」；
  - 后续所有文件上传与 CDR 上报均自动附带 `Authorization: Bearer <token>` 认证头；若 token 失效或账号错误返回 401 并显示警告提示。
- **通话时长精确统计**：
  - 客户端计时严格绑定于通话应答确认状态（`PJSIP_INV_STATE_CONFIRMED`，即 200 OK 确认建立），不在早期媒体（180 Ringing / 183 Session Progress）提前计时；
  - 振铃未接、早期媒体响铃放弃等未接通通话，时长严格记录为 0 秒（标记为未接通）；
  - 通话挂断（`PJSIP_INV_STATE_DISCONNECTED`）时按接通时刻计算真实通话秒数并异步触发上报。
- **通话结束自动上报 CDR 与多端精准去重**：
  - 挂断后异步向后台发送 `POST /api/cdr`，携带 `call_id`（唯一 SIP Call-ID）、`caller`（主叫）、`callee_or_room`（被叫或房间号）、`started_at`（开始时间 ISO 8601）、`duration_sec`（通话时长秒数）；
  - **基于 Call-ID 与时序边界的精准去重**：后台优先通过唯一 SIP `call_id` 去重；无 `call_id` 时按精确主被叫与时序判定（严格区分 A->B 与 B->A 回拨，且连续发生的短通话不会被误吞），去重时合并保留最大有效时长；
  - 上报成功后自动记录日志，并刷新客户端通话记录列表与统计看板。
- **通话记录看板与丰富交互**：
  - 右侧栏新增「📊 通话记录与统计 (CDR)」标签页；
  - 顶部看板实时统计呈现：**通话总数**、**总通话时长**、**平均通话时长**、**房间同时在会峰值人数**（来自后台 `GET /api/cdr/stats`，基于真实通话时间区间重叠扫描算法计算，反映瞬时并发人数，且各房间独立统计绝不互相污染）；
  - 列表区表格化呈现每条通话记录的 ID、主叫、被叫/房间、开始时间、通话时长与快捷操作；
  - 支持「🔄 刷新记录」、「只看我」与「查看全部」过滤筛选；
  - **双击行交互**：双击任意通话记录行，自动将对方填入拨号框，并 **自动跳转至「💬 消息与文件」标签页且光标聚焦至输入框**，操作行云流水；
  - **快捷操作列**：表格右侧配备专属按钮 `💬`（切换聊天）、`📞`（发起语音呼叫）、`📹`（发起视频呼叫）；
  - **右键上下文菜单**：行支持右键唤出菜单，包括「💬 切换至消息聊天」、「📞 发起语音呼叫」、「📹 发起视频呼叫」、「📋 复制对方号码/房间」。

### 5. 房间 MCU 与音视频会议（阶段 5 新增）
- **会议房间看板与列表**：
  - 右侧栏新增专属「👥 会议房间 (MCU)」标签页；
  - 启动、登录成功或点击「🔄 刷新房间」时，客户端调用后台 `GET /api/rooms` 获取全量会议室信息；
  - 表格清晰展示：房间 ID、房间名称、SIP 呼叫 URI（格式严格为 `room-<id>`）、最大容量（8 人）、当前/峰值在会人数，以及操作列（`🎥 加入会议`、`💬 选定`）；
  - **双击房间行**：自动将房间 URI 填入呼叫输入框，并无缝切回「💬 消息与文件」标签页，方便针对房间发消息或发起呼叫。
- **新建会议房间**：
  - 点击「➕ 新建会议房间」，弹出新建对话框，输入房间名称与最大参会人数（1~8 人，默认 8 人）；
  - 客户端调用后台 `POST /api/rooms`，**严格使用后台生成并返回的官方 SIP URI（如 `room-103`）**，杜绝客户端本地私自伪造或拼凑房间号；
  - 创建成功后自动刷新列表，并将新房间填入呼叫输入框，准备呼叫。
- **加入 MCU 会议与 3×3 视频画面合成**：
  - 点击操作列「🎥 加入会议」或在拨号框输入 `room-<id>` 并点击「视频呼叫」，客户端发起 `INVITE sip:room-<id>@lab`；
  - **信令路由**：Kamailio 识别 `room-*` 前缀，自动将呼叫路由至 FreeSWITCH MCU 容器（`freeswitch:5080`），一对一呼叫绝不经过 MCU；
  - **视频画布**：FreeSWITCH `mod_conference` 自动将最多 8 路参会人画面合成为 720p30 H.264 3×3 九宫格混流画布，客户端视频窗口直接渲染由服务端合成的视频画面，并打印 `"MCU 会议室视频流已接通，正在渲染 3×3 混流画布"`，无需客户端执行复杂的本地混流或部署 SFU 客户端组件；
  - **音频混合**：MCU 服务端统一处理回声消除与音频混音（PCMU/PCMA），参会人员可直接实时多人通话；
  - **容错与状态解耦**：当房间达到最大人数（8 人）时，第 9 人加入被 MCU 拒绝（SIP 486 Busy Here 或 403）；客户端一对一呼叫挂断或失败时，绝不自动降级或误拨入 MCU，保持明确的业务边界。

## 接口与协议规范

### 1. 信令与账号约定
- **SIP 域**：`lab`，用户 `sip:<user>@lab`。
- **一对一通话**：`INVITE sip:<user>@lab`（支持音视频媒体双向协商）。
- **多人会议室呼叫**：`INVITE sip:room-<id>@lab`（由 Kamailio 路由至 FreeSWITCH MCU 5080，进入 `video-mcu-3x3` 会议室）。
- **文字消息**：`MESSAGE sip:<user>@lab`，消息体为 UTF-8 纯文本。
- **文件元数据通知**：
  ```text
  [FILE] <文件名> | <字节数> | <HTTP下载URL>
  ```
  例如：`[FILE] sample.pdf | 1048576 | http://192.168.1.10:8080/api/files/1`

### 2. 后台 HTTP 接口（Spring Boot）
| 接口 | 方法 | 请求类型 | 关键字段 / 参数 | 说明 |
|---|---|---|---|---|
| `/api/health` | GET | - | - | 服务健康探活，返回 `{"status":"ok","esl":{"enabled":true,"connected":true,"target":"127.0.0.1:8021"}}` |
| `/api/login` | POST | `application/json` | `username`, `password` | 验证用户密码并颁发 Bearer Token（演示账号密码同用户名） |
| `/api/files` | POST | `multipart/form-data` | `file` (文件流), `from` (发送人), `to` (接收人) | 上传文件，返回包含下载 URL 的 JSON |
| `/api/files/{id}` | GET | - | 路径参数 `id` | 流式下载二进制文件，带 Content-Disposition |
| `/api/cdr` | POST | `application/json` | `call_id` (可选), `caller`, `callee_or_room`, `started_at`, `duration_sec` | 通话结束上报 CDR，支持 Call-ID 精确去重与连续通话防误吞 |
| `/api/cdr` | GET | - | `caller`, `callee`, `limit` (可选) | 拉历史通话记录列表（按 ID 倒序） |
| `/api/cdr/stats` | GET | - | - | 通话与房间统计（总次数、总时长、平均时长、房间并发峰值人数） |
| `/api/rooms` | GET | - | - | 获取所有会议房间列表（含 SIP URI、最大容量与实时在会人数） |
| `/api/rooms` | POST | `application/json` | `name`, `max_members` (可选) | 创建新会议房间，返回官方分配的 `room-<id>` SIP URI |
| `/api/rooms/{id}` | GET | - | 路径参数 `id` (数字 ID 或 `room-101`) | 查询单个房间详情与实时状态 |
