## 原审查问题已修复

### P2 保留被叫端的合法 CDR 上报

问题位置：[PR head CdrController.java 第 62 行](https://github.com/BUPTAL1S/software-practise/blob/11d76cf034e089d6d036da2c8db6949c57bacb70/admin/src/main/java/com/lab/sipim/web/CdrController.java#L62)。

新增条件只允许非管理员上报 caller 与当前用户身份相同的记录。现有 [SipService](../../client/src/main/java/lab/sip/client/SipService.java) 在被叫端保留远端主叫和本地被叫，并发出 callEnded；[MainApp](../../client/src/main/java/lab/sip/client/MainApp.java) 不区分呼入呼出，均以当前登录 token 上报。

正常场景为 1003 呼叫 1002。1002 的请求是：

```http
POST /api/cdr
Authorization: Bearer <1002 的有效 token>
Content-Type: application/json

{"call_id":"review-incoming","caller":"1003","callee_or_room":"1002","started_at":"2026-10-30T08:00:00Z","duration_sec":20}
```

| 检出 | 1003 主叫端上报 | 1002 被叫端上报 |
| --- | --- | --- |
| main 6c91ecb | 200 | 200 |
| PR49 11d76cf | 200 | 403 |

直接影响是普通被叫客户端出现 CDR 上报失败；若主叫端的 HTTP 上报未成功，这条合法通话记录无法由被叫补上。即使主叫已成功上报，被叫也不能参与原有双端去重及较大有效时长合并。

修复要求：根据合法参与者校验权限，保留真实 caller/callee；对已有 Call-ID 校验记录参与者，拒绝无关第三人；保持双端去重、时长合并、反向回拨和连续短通话的语义。不能通过把被叫上报的 caller 改为自己来绕过检查。

回归至少覆盖主叫、被叫、无关用户、未登录、过期会话以及已有 Call-ID 的修改。修复后将本轮探针迁入正式测试。
