# 分工：后台

负责单体 Spring Boot + 管理查询。不拆微服务。

## 做

- 四张表：用户、房间、CDR、文件索引（见 [admin/README.md](../admin/README.md)）
- HTTP：注册/登录、创建房间（返回 `room-<id>`）、上传下载、通话记录、人数/通话量统计
- ESL 客户端：订阅入会/离会，更新房间人数；不要在这里发呼叫命令（房间由用户 INVITE 加入）
- 给客户端提供文件存储（本地目录即可，不要上 OSS）

## 不做

- 不接 OpenCallHub、不做技能组
- 不写 SIP 协议栈、不改 Kamailio cfg
- 不上 Redis / 消息队列
- 不在后台混流或转发 RTP

## 接口

- 客户端：JSON HTTP，鉴权用简单 token 或 session（一种即可）
- 信令：Kamailio 静态测试账号；后台自己用 SQLite 用户表。不要把 SIP REGISTER 写入业务库
- ESL：只收事件，把 `room-<id>` 与人数写回房间表

优先「Kamailio 静态测试账号 + 后台自己的用户表」，避免一上来同步两套鉴权。阶段 4 若有余力再把 SIP 密码和后台用户对齐。

## 按阶段交付

| 阶段 | 你交出什么 |
|---|---|
| 1 通话底座 | 空工程能跑；用户表能插入测试数据 |
| 2 视频界面 | 登录接口给客户端 |
| 3 消息文件 | 文件上传下载 |
| 4 后台统计 | CDR、统计页（通话次数、时长、房间人数峰值） |
| 5 房间 MCU | 已在 main：`POST /api/rooms` 返回 `room-<id>`，ESL 按房间写 `memberCount` |
| 6 交付 | 演示用管理页能查记录 |

和客户端对齐 HTTP 基址与字段。和信令对齐 ESL 密码、房间 URI。
