# 整体规划

三人按角色分工，见同目录另外三份文档。技术选型已锁定，不要加新中间件。

## 锁定项

- SIP 代理：Kamailio（不用 miniSIPServer）
- 客户端：JavaFX + PJSIP 2.17 PJSUA2
- 一对一：Kamailio 直连，不进 MCU
- 房间：最多 8 人，Kamailio 把 `room-*` 转到 FreeSWITCH MCU（3×3）
- 文字：SIP MESSAGE；文件：HTTP（不做 MSRP）
- 后台：一个 Spring Boot + SQLite；ESL 只听入会 / 离会 / 人数
- 原生库：Windows x64 与 macOS arm64 各一份，不入库，见 `native/`

## 系统怎么连

```
JavaFX 客户端 (Win / Mac)
    REGISTER / INVITE / MESSAGE  -->  Kamailio
    一对一 INVITE 用户            -->  Kamailio 转发对端
    INVITE sip:room-101@lab       -->  Kamailio --> FreeSWITCH 会议室
    房间媒体 UDP 21000-21099      -->  其他电脑打校园网 IP，本机打 127.0.0.1
    HTTP 上传下载                 -->  Spring Boot
FreeSWITCH ESL 事件               -->  Spring Boot（按房间更新当前人数）
```

服务器只跑一套：本机 Docker（`server/docker-compose.yml`）。两台验收电脑都连这套服务。

## 阶段

| 阶段 | 目标 | 验收 |
|---|---|---|
| 1 通话底座 | REGISTER + 一对一音频 | 两台电脑互相振铃、通话 |
| 2 视频界面 | 视频 + 主界面 | 双向画面 |
| 3 消息文件 | MESSAGE + HTTP 图/语音/短视频 | 能发能看 |
| 4 后台统计 | 用户、CDR、简单统计 | 管理端能查 |
| 5 房间 MCU | 上限 8，3×3 | 同一 `sip:room-101@lab` 进 6–8 路 |
| 6 交付 | 双机彩排、报告、打包 | 压缩包名：小组编号-实践阶段二 |

阶段 1–5 已在 `main`。`room-*` 的 INVITE 进入 FreeSWITCH；一对一仍不进 MCU。房间 MESSAGE 回 `405 Room has no chat`，没有群聊。阶段 6 是便携包、双机彩排和交付打包，已经在做。

启动信令用 `server/start-kamailio.ps1` 或 `start-kamailio.sh`。脚本会先 `docker compose --profile mcu up -d`，把新的校园网 IP 和 Docker 网关写进 `kamailio/public-ip.defs`，再重启 Kamailio。不带 `mcu` 这个 profile，FreeSWITCH 不会起来。

分析与图见 [用户分析.md](用户分析.md)、[需求分析.md](需求分析.md)、[UML.md](UML.md)。信令各阶段见 [信令阶段回顾.md](信令阶段回顾.md)。

## 角色接口（只这几条）

| 从 | 到 | 约定 |
|---|---|---|
| 客户端 | Kamailio | SIP 域 `lab`，用户 `sip:<id>@lab` |
| 客户端 | 房间 | `sip:room-<id>@lab`，id 由后台创建 |
| 客户端 | 后台 | HTTP 注册/登录、上传文件、拉历史 |
| 信令 | FreeSWITCH | 仅 `room-*` 进会议；一对一不经过 MCU |
| 后台 | FreeSWITCH | ESL 入会/离会/当前人数 |

详细依赖版本见 [deps.md](deps.md)。

## 不做

OpenCallHub、Jitsi/SFU、mjSIP 主引擎、Redis、MSRP、把一对一塞进 MCU。
