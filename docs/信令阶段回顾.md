## 按文件：完成的功能和所用规则

这里的「算法」是路由判断和字符串匹配，不是排序或图搜索。Kamailio 的在线用户表 `usrloc` 按 AOR（`sip:用户@lab`）做哈希查找。

### [server/kamailio/kamailio.cfg](../server/kamailio/kamailio.cfg)

阶段 1 到 3 的转发都在这个文件。阶段 2 没有改它：不解析、不改写 SDP。

完成的功能：

- REGISTER 写入内存位置表，不鉴权。
- 一对一 INVITE / ACK / BYE / CANCEL 按位置表转发。
- `room-*` 不查位置表。INVITE / SUBSCRIBE 转到 `sip:freeswitch:5080`；MESSAGE 回 `405 Room has no chat`。
- 对话内请求按 Record-Route 松散路由，宿主机腿改写到 `host.docker.internal`。
- REGISTER 时若 Contact 声明了 `methods` 却没有 MESSAGE，补上后再保存，避免后面的 MESSAGE 被 `405`。

所用规则：

1. **方法分发。** 先看 `Max-Forwards` 和语法。有 To-tag 的走对话内；`CANCEL` 只跟已有事务；`REGISTER` 只 `save`；其余本域请求先排除 `room-*`，再 `lookup`。
2. **本域判断**（`route[LOCAL_DOMAIN]`）。请求 URI 的主机是 `lab`、探测到的校园网 IP、`127.0.0.1` 或 `localhost`，或者 `is_myself()` 命中，才算打给本代理。
3. **位置查找。** `lookup("location")` 用用户部分在 usrloc 哈希表里找 Contact。找不到回 404。`method_filtering=1` 时再做集合过滤：Contact 的 `methods` 列表不含当前方法就跳过，全部被跳过则回 405。
4. **房间前缀。** 用户部分匹配正则 `^room-` 就结束，不查位置表。MESSAGE 直接 405。其余方法把 `$du` 设成 `sip:freeswitch:5080`，INVITE 和 SUBSCRIBE 先走 `DOUBLE_RR` 再转发。这是前缀分流，不是负载均衡。阶段 1–4 这里曾是直接 480。
5. **来源分类**（`FROM_DOCKER_HOST`）。源地址是回环、`172.16.0.0/12` 里以 `.1` 结尾的网桥网关，或 `192.168.65.0/24`，判成 Docker 宿主机。这是正则，不是选路算法。
6. **下一跳分类**（`NEXTHOP_ON_DOCKER_HOST`）。优先看 `$du`，否则看请求 URI。主机是回环，或是校园网 IP 且端口不是 `5060`，判成宿主机上的客户端。端口 `5060` 是代理自己，不能当客户端。
7. **双边 Record-Route**（`DOUBLE_RR`）。主叫腿、被叫腿各自选一个回程地址：宿主机用 `127.0.0.1:5060`，校园网用 `PUBLIC_IP:5060`。两边相同只插一条；不同则两条都加 `r2=on`，交给 SIP 松散路由一次剥掉。这是 RFC 3261 的 loose routing，不是自写的最短路径。
8. **自环剥离**（`STRIP_SELF_RR`、`HOP_IS_PROXY`）。下一跳主机是代理且端口是 `5060` 时，再 `loose_route` 一次；还是自己就用 To 里的用户名重新查 usrloc。
9. **宿主机改写**（`TO_DOCKER_HOST`）。下一跳在宿主机上、端口不是 `5060` 时，把目的改成 `sip:host.docker.internal:端口`。端口是 `5060` 则回 `482 Loop Detected`。
10. **失败重试**（`failure_route`）。只对 BYE / ACK / CANCEL 重查一次位置表。用事务标志位挡住第二次重试，避免环路。To 或请求 URI 的用户部分是 `room-*` 时不查位置表，改送到 `sip:freeswitch:5080`。
11. **补 MESSAGE**（`ALLOW_MESSAGE`）。Contact 不含 `methods=` 则返回。含 `methods=` 且已有 MESSAGE 则返回。否则用正则替换：引号形式 `methods="..."` 或无引号形式，把 `MESSAGE` 接到列表末尾，再重新解析报文后 `save`。
12. **房间媒体地址**（`MCU_MEDIA`）。只在 `room-*`、下一跳主机是 `freeswitch`、或下一跳端口是 `5080` 时进入。一对一不进。端口 `5080` 但主机不是 `freeswitch` 时，把下一跳改回 `sip:freeswitch:5080`。SDP 里只替换 `IN IP4` 后面的地址，端口不动：宿主机发出的 SDP 把 `PUBLIC_IP` 换成 `GATEWAY_IP`（容器访问宿主机的 Docker 网关）；回到宿主机的会议 SDP 换成 `127.0.0.1`。其他电脑的 SDP 保持 `PUBLIC_IP`。`subst_body` 的替换串不能在运行时展开变量，所以这两个地址由启动脚本写成 `#!substdef`。

### [server/start-kamailio.ps1](../server/start-kamailio.ps1) 与 [server/start-kamailio.sh](../server/start-kamailio.sh)

完成的功能：探测本机应通告的 IPv4，写成 `PUBLIC_IP`。容器起来后读 Kamailio 所在网络的网关，写成 `GATEWAY_IP`。两者都进 `kamailio/public-ip.defs`，不进 git。然后 `docker compose --profile mcu up -d --force-recreate freeswitch`，再重启 Kamailio。不带 `mcu` 这个 profile 时，FreeSWITCH 不会起来。Windows 脚本是带 BOM 的 UTF-8，并会把 Docker Desktop 的 `docker.exe` 放进 PATH；同时尝试添加防火墙规则「UDP 21000-21099」，没有管理员权限时只打印命令。

所用规则是一次线性扫描，带优先级，不是选最优度量：

- 网卡名匹配 `loopback|docker|vmnet|vbox|vethernet|hyper-v|vmware|virtualbox` 等则跳过。
- 地址是 `127.0.0.0/8`、`169.254.0.0/16`、`192.168.154.0/24`、`192.168.204.0/24` 则跳过。
- 剩下的地址里，先记住第一条 `10.0.0.0/8`；没有的话再记住第一条 RFC1918（`192.168.0.0/16` 或 `172.16.0.0/12`）。
- 两条都没有就失败退出。

Shell 脚本把同样的规则放在 [server/detect-lan-ip.sh](../server/detect-lan-ip.sh)，用 `ifconfig` 或 `ip addr` 扫接口。PowerShell 脚本用 `Get-NetIPAddress`。

### [server/docker-compose.yml](../server/docker-compose.yml)

完成的功能：定义两个容器和端口，不包含业务数据库。

- Kamailio：`5060` UDP/TCP，配置目录挂进 `/etc/kamailio`，`PUBLIC_IP` 来自 `.env`。
- FreeSWITCH：镜像 `safarov/freeswitch:1.11.3`，compose profile 是 `mcu`。SIP 发布 `5080` UDP/TCP。会议 RTP 发布 `21000-21099/udp`。ESL 只发布在 `127.0.0.1:8021`。`./freeswitch` 挂到容器里的 `/tmp/freeswitch-custom`。入口先拷镜像自带配置，再盖上仓库里的文件，然后做三处固定替换：`external_rtp_ip` / `external_sip_ip` 换成环境变量 `PUBLIC_IP`；把注释掉的 RTP 起止端口改成 `21000` 和 `21099`；H.264 编码器改成 Baseline、Level 3.0。最后执行镜像原来的 `/entrypoint.sh`。

没有调度算法。端口是固定映射。阶段 4 用过的 `lab-entrypoint.sh` 已经不在这条启动路径上。

## 阶段 1：通话底座

目标：两个客户端经 Kamailio 注册，一对一能振铃、通话、挂断。房间先不进会议室。

### 写了什么

主要文件是 [server/kamailio/kamailio.cfg](../server/kamailio/kamailio.cfg)、[server/docker-compose.yml](../server/docker-compose.yml)、[server/start-kamailio.ps1](../server/start-kamailio.ps1)、[server/start-kamailio.sh](../server/start-kamailio.sh)。

- Kamailio 用镜像 `ghcr.io/kamailio/kamailio-ci:5.8.3-alpine`，只映射 `5060` UDP/TCP。没有数据库，注册放内存（`usrloc db_mode=0`），阶段 1 不校验 SIP 密码。
- 启动脚本探测校园网 IPv4（优先 `10.0.0.0/8`，跳过回环、Docker、VMware），写入不入库的 `kamailio/public-ip.defs` 和 `server/.env`。`listen` 绑 `0.0.0.0:5060`，`advertise` 用探测到的公网侧地址。
- 域是 `lab`。`alias` 必须带端口，而且不能加引号，否则 `is_myself()` 匹配不上，BYE 会被当成打给代理自己。
- `room-*` 直接回 `480 MCU not ready in phase 1`。
- 其余本域请求 `lookup("location")` 后 `t_relay`。找不到用户回 404。
- 对话内请求走 `loose_route`。宿主机上的下一跳改写到 `host.docker.internal`，避免容器里的 `127.0.0.1` 指回容器自己，也避免打回被 Docker 占用的宿主机 `5060`。

双边 Record-Route 在 `route[DOUBLE_RR]`：

- 这一腿是 Docker 宿主机上的客户端时，Record-Route 用 `127.0.0.1:5060`。
- 这一腿是校园网上的另一台电脑时，用探测到的校园网 IP。
- 两边地址不同就插两条，并打开 `enable_double_rr`，这样 `loose_route` 会一次剥掉两条。

### 完成的功能

- 账号 `1001`–`1008` 可以 REGISTER，返回 200。
- `1001` 和 `1002` 可以互相 INVITE、振铃、接通、听到声音。
- 任一方挂断，对端能收到 BYE，通话变成 DISCONNECTED。
- 本机客户端 SIP 服务器填 `127.0.0.1`，组员填启动脚本打印的校园网 IP。域都填 `lab`，传输用 TCP。

### 遇到的困难

- Docker Desktop 访问自己的校园网地址 `10.x:5060` 会头发夹丢包。本机只能连 `127.0.0.1:5060`，对端仍然必须填校园网 IP。Domain 不能改成 `127.0.0.1`。
- Contact 如果写成 `127.0.0.1` 或 Docker 网桥地址，对端的 INVITE 回不来。客户端要通告校园网 IP，监听仍绑 `0.0.0.0`。本机端口若是 `5060` 会被 Kamailio 占用，客户端会自动改到 `5062`。
- 只做一条 Record-Route 时，宿主机和校园网各有一个地址，BYE 只能回到其中一边。改成按腿插入两条之后，又出现过「配置写了双 RR，实际只插进一条」和 `alias="IP:5060"` 带引号永远匹配失败。BYE 因此停在本端，对端一直 CONFIRMED。
- Windows 上直接跑 `start-kamailio.ps1` 时，无 BOM 的 UTF-8 会被 PowerShell 5 当成系统 ANSI，中文注释把脚本解析坏。脚本需要保存成带 BOM 的 UTF-8。
- 校园网防火墙配置文件经常是 Public。只放了回环、没放 `5060` 时，对端注册会超时。

## 阶段 2：视频 SDP

目标：一对一的视频 SDP 原样穿过 Kamailio，并和客户端约定同一套 H.264。双向画面是客户端的事。

### 写了什么

这一阶段没有改转发逻辑。`kamailio.cfg` 本来就不加载 `rtpengine` / `sdpops`，INVITE 在 `lookup` 之后原样 `t_relay`。

写进 [server/kamailio/README.md](../server/kamailio/README.md) 和 [docs/分工-信令MCU.md](分工-信令MCU.md) 的约定是 PJSIP 2.17 OpenH264 的默认值：

| 项 | 值 |
|---|---|
| rtpmap | `97 H264/90000` |
| profile-level-id | `42e01e`（Constrained Baseline，Level 3.0） |
| packetization-mode | `1` |

Win 和 Mac 只用这一套，不再同时放 ffmpeg / VideoToolbox 的另一个动态载荷。

### 完成的功能

用两个已注册账号走了一条带 `m=audio` 和 `m=video` 的呼叫：

- INVITE 和 200 OK 的 SDP 正文进出代理后不变，H.264 载荷仍是 97，端口没有被改成 0。
- 对话内 re-INVITE、ACK、BYE 仍然到达对端。
- 反向呼叫同样通过。
- `sip:room-101@lab` 仍是 `480`。

### 遇到的困难

- 视频媒体不经过 Kamailio，是两端按 Contact 里的校园网 IP 直连 RTP。防火墙如果只放行 `5060`，信令是通的，画面是黑的。
- 本机当时的 `pjsua2.dll` 还是阶段 1 用 `--disable-video` 编的。客户端会显示「阶段 1 纯音频模式」，视频呼叫被降级。这不是代理删了视频行，要按 `native/windows-x64/BUILD.md` 用 OpenH264 重编动态库。后来本机换成了带 H.264 的库，依赖里要有 `openh264.dll`（以及 `libopenh264-7.dll`）。
- Mac 端如果仍用 VideoToolbox、Windows 用 OpenH264，SDP 的 profile 可能对不齐，协商失败后通话会自己断。后来客户端把 Mac 也对齐到同一套 OpenH264。

## 阶段 3：一对一 MESSAGE

目标：已注册用户之间的文字原样转发。文件走后台 HTTP，不走 SIP，也不做离线存储。

### 写了什么

`lookup` 之后本来就会转发 MESSAGE，所以一开始没有为文字单独写路由。真正加的是 REGISTER 上的 `route[ALLOW_MESSAGE]`，并加载 `textopsx.so`。

`modparam("registrar", "method_filtering", 1)` 会看 Contact 里的 `methods`。列表里没有 MESSAGE 时，`lookup` 返回 -2，脚本回 `405 Method Not Allowed`。处理是：

- Contact 没写 `methods`：不动。现有 Java 客户端就是这种，本来就能发文字。
- 写了 `methods` 但没有 MESSAGE：在 `save()` 之前用 `subst` 补上 `MESSAGE`，再 `msg_apply_changes()`。
- 不把 `method_filtering` 关掉，这样没声明 INVITE 的联系人不会因此收到 INVITE。

未注册用户仍然 `404`。当时 `room-*` 的 MESSAGE 也是 `480`。阶段 5 起房间 MESSAGE 改为 `405 Room has no chat`，房间 INVITE 改送会议室。一对一文字不经过房间。

### 完成的功能

- `1005` 发给已注册的 `1006`：`text/plain` 正文不变，主叫收到 `200`。
- 发给未注册用户：`404 Not Found`。界面上就是「发送未送达」。
- Contact 的 `methods` 不含 MESSAGE 时，注册后再发，得到 `200`，保存下来的 Contact 里已经有 MESSAGE。
- 带视频 SDP 的 INVITE / BYE，以及 `room-101` 的 `480`，都还在。

### 遇到的困难

- 第一次用 `{s.strstr,...}` 判断 Contact，Kamailio 5.8 没有这个变换，配置检查直接失败，改成了 `=~`。
- `subst` 只改报文原文。`save()` 用的是已经解析过的 Contact，不调用 `msg_apply_changes()` 的话，日志里像是补上了 MESSAGE，usrloc 里仍是旧的，`405` 还在。
- `msg_apply_changes()` 在 `textopsx` 里，不加载这个模块就找不到命令。
- 本机只开了一个客户端时，给 `1002` 发文字必然是 `404`。这是对端没注册，不是 MESSAGE 路由坏了。

## 阶段 4：ESL

目标：后台能连上 FreeSWITCH 的事件口，订阅进出房间的事件。这一阶段不把呼叫送进会议室。

下面写的是阶段 4 当时的做法。镜像版本、启动入口和 `room-*` 的 480 已在阶段 5 替换，以阶段 5 一节为准。

### 写了什么

- [server/docker-compose.yml](../server/docker-compose.yml)：镜像钉成 `safarov/freeswitch:1.10.12`。SIP 只映射 `5080`，ESL 映射 `8021`。不占用 Kamailio 的 `5060`。不再使用 `mcu` profile，也不要把空的 `server/freeswitch/` 整目录挂到 `/etc/freeswitch`。
- [server/freeswitch/lab-entrypoint.sh](../server/freeswitch/lab-entrypoint.sh)：第一次启动时拷贝镜像自带的 vanilla 配置，然后改两处。
  - `listen-ip` 从 `::` 改成 `0.0.0.0`。
  - `apply-inbound-acl` 改成 `rfc1918.auto`。
- 文档写明给后台的接口：`127.0.0.1:8021`，密码 `ClueCon`，订阅 `CHANNEL_CREATE`、`CHANNEL_DESTROY`、`conference::maintenance`。
- [docs/deps.md](deps.md) 里的 FreeSWITCH 版本改成 `1.10.12`。
- `start-kamailio.ps1` / `start-kamailio.sh` 在拉起 Kamailio 的同时拉起 FreeSWITCH。

`kamailio.cfg` 里 `room-*` 的 `480` 没有改。

### 完成的功能

- 连 `127.0.0.1:8021`，`auth ClueCon` 返回 `+OK accepted`。
- 订阅上述三个事件，返回 `+OK event listener enabled plain`。
- 镜像里已经有 `mod_conference`、`mod_event_socket`、`mod_av`，并且注册了 `H264 Video`。当时会议模板里已有 `3x3`、`1280x720`、30 帧的混流配置，呼叫还没转到那里。阶段 5 才把 `room-*` 送进去，并用仓库里的 `video-mcu-3x3` 配置替换镜像自带模板。
- 一对一仍只走 Kamailio。

### 遇到的困难

- Docker Hub 直接拉 `safarov/freeswitch:1.10.12` 超时。从镜像站拉下来后再打上原来的名字，compose 里仍然写官方镜像名。
- 镜像默认把 ESL 绑在 `::`。这台 Docker 没有 IPv6，日志是 `Cannot get information about IP address ::`，端口起不来。
- 不写 ACL 时，模块默认用 `loopback.auto`。从 Windows 连发布出来的 `8021`，容器里看到的是 Docker 网桥地址（`172.16.0.0/12`），不是 `127.0.0.1`，会直接 `Access Denied, go away`。改成允许私网地址后，宿主机可以登录。密码仍然要 `ClueCon`。
- `lab-entrypoint.sh` 在 Windows 上若被检出成 CRLF，容器里的 `sh` 会把 `set -e` 读坏（`illegal option`），FreeSWITCH 不断重启。脚本必须保持 Unix 换行。仓库里用 `.gitattributes` 把 `server/freeswitch/*.sh` 固定为 `eol=lf`。
- 入口脚本如果把整个配置目录挂进容器，空目录会盖掉镜像里的 `freeswitch.xml`。所以只挂这一个启动脚本，配置仍由镜像在第一次启动时拷进容器。

## 阶段 5：房间 MCU

目标：只有 `sip:room-<id>@lab` 进 FreeSWITCH。同一间最多 8 人，画面是 3×3，第 9 人拒绝。一对一仍然不进 MCU。房间不提供群聊。

这一阶段的信令提交是 `b16d72d`，ESL 网段补充是 `0de5857`。后台按房间写人数（`ded377e`）和客户端房间界面（`79c9be1`）是另外两个角色的代码，这里只写信令怎么接上。

### 写了什么

- [server/kamailio/kamailio.cfg](../server/kamailio/kamailio.cfg)：用户部分匹配 `^room-` 时不再回 480。MESSAGE 回 `405 Room has no chat` 并结束。其它方法把 `$du` 设为 `sip:freeswitch:5080;transport=` 加上当前传输，INVITE 和 SUBSCRIBE 先 `DOUBLE_RR`，再 `RELAY`。不 `lookup("location")`。
- [server/docker-compose.yml](../server/docker-compose.yml)：FreeSWITCH 改为 `safarov/freeswitch:1.11.3`，放进 profile `mcu`。`5080` 对校园网发布。`8021` 只绑宿主机 `127.0.0.1`。配置目录挂到 `/tmp/freeswitch-custom`，由入口在容器里拷进 `/etc/freeswitch`。
- [server/freeswitch/dialplan/default.xml](../server/freeswitch/dialplan/default.xml) 与 [conference.conf.xml](../server/freeswitch/autoload_configs/conference.conf.xml)：`room-*` 进入名为 `video-mcu-3x3` 的会议。上限 8，布局 `3x3`，画布 `1280x720`，30 帧。
- [server/freeswitch/autoload_configs/event_socket.conf.xml](../server/freeswitch/autoload_configs/event_socket.conf.xml) 与 [acl.conf.xml](../server/freeswitch/autoload_configs/acl.conf.xml)：ESL 听 `0.0.0.0:8021`，密码 `ClueCon`，来源必须落在名单 `lan`。
- 启动脚本改为 `docker compose --profile mcu up -d`。随后会重建 FreeSWITCH，让新的校园网 IP 进入会议室 SDP，并重启 Kamailio 以读入 `public-ip.defs`。
- 会议室 RTP 固定 `21000-21099/udp`，和 compose 端口发布一致。`external_rtp_ip` / `external_sip_ip` 用同一个 `PUBLIC_IP`，不再留在 `127.0.0.1`。本机客户端这一路的 SDP 由 Kamailio 改写：去 FreeSWITCH 的地址改成 Docker 网关，回来的会议地址改成 `127.0.0.1`。其他电脑仍用校园网 IP。一对一不改 SDP。
- H.264 使用 Baseline、Level 3.0，并打开 late negotiation，沿用客户端 INVITE 里的 `42e01e` 和 `packetization-mode=1`。

后台 [EslEventListener](../admin/src/main/java/com/lab/sipim/esl/EslEventListener.java) 连 `127.0.0.1:8021`，认证后订阅 `conference::maintenance`、`CHANNEL_CREATE`、`CHANNEL_DESTROY`。真正改人数的只有会议维护事件：用 `Conference-Name` 找到这一间，`add-member` 和 `del-member` 把 `Conference-Size` 写入该房间的 `memberCount`，`conference-destroy` 写成 0。找不到房间就忽略，不会把人数加到别的房间上。

### 完成的功能

- `INVITE sip:room-101@lab` 被送到 FreeSWITCH `5080`，拨号计划把它放进 `room-101@video-mcu-3x3`。
- 一对一 `INVITE sip:1002@lab` 仍走 `lookup`，不进 MCU。
- 向 `sip:room-101@lab` 发 MESSAGE 得到 `405 Room has no chat`。给已注册用户发文字仍是 200。
- 预置房间 `room-101`、`room-102`。`POST /api/rooms` 在不指定 URI 时返回 `room-<数字 id>`，`max_members` 只能是 8。
- 健康检查里的 `esl.connected` 为真时，入会、离会会改这一间的 `memberCount`。
- 第 9 人由 `max-members` 拒绝。拨号计划会先 `answer`，会议室满员后日志是 `Conference room-101 is full`，播放 `conf-locked.wav`，这一路随后结束，不会留在成员列表里。每人收到的是混流后的一路画面。
- 本机进房间时，200 OK 的 `c=` 是 `127.0.0.1`，端口在 `21000-21099`。从其他电脑看，`c=` 是校园网 IP，端口范围相同。视频行是 `97 H264/90000`，`profile-level-id=42e01e`，`packetization-mode=1`。

### 遇到的困难

- 漏写 `--profile mcu` 时，`docker compose up -d` 只拉 Kamailio，房间 INVITE 没有 FreeSWITCH 可去。
- 不能把 `server/freeswitch/` 直接挂到 `/etc/freeswitch`。目录一旦是空的，会盖掉镜像里的 `freeswitch.xml`。现在先拷 vanilla，再把仓库里的文件盖上去。
- ESL 若听在 `::`，这台没有 IPv6 的 Docker 起不来。配置里写成 `0.0.0.0`。发布端口若对全网开放，校园网别人也能撞 `8021`，所以只绑 `127.0.0.1`。
- 从 Windows 连发布出来的 `8021`，容器里看到的源地址是 Docker 网桥，不是 `127.0.0.1`。名单 `lan` 要同时放行 `10/8`、`127/8`、`172.16/12`、`192.168/16`，否则认证前就是 `Access Denied`。
- 进了房间以后发文字得到 405，是前缀规则故意拒绝的，不是 MESSAGE 转发坏了。私聊要把对端改回用户号。
- 只发布 `5080` 时，人能进房间，声音和画面仍在容器里。会议 RTP 要单独映射 `21000-21099`。本机若把媒体发到自己的校园网 IP，Docker 会头发夹丢包，所以这一跳改成 `127.0.0.1` 和 Docker 网关，不改一对一。
