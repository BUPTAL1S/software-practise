# 管理工作台六项改进交付（2026-11-06）

开发基线为 `b9c1cb1`（已合并视频输入修复 PR #64）。变更分成八个递进 PR：
组合筛选、迁移/审计基础、账号状态、数据库分页、房间管理、日期/CSV、运维/操作记录、交付验证。
它们按顺序审阅与合并，最终累计版本统一打包。没有部署到协作者的运行实例。

## 已实现行为

1. 话单主叫与被叫条件同时生效，旧客户端数组接口保留，limit 限定 1–500。
2. 账号禁用/恢复保留原数据库 ID、用户名、分机号、密码和历史；禁用与恢复都撤销原 HTTP token。
   禁用用户从普通通讯录隐藏，管理列表可以筛选正常/禁用账号。旧 DELETE 用户入口也执行禁用。
   管理员与当前账号受保护。账号和分机号采用共同保留空间；启动时回填历史身份，避免已删除身份被重新注册。
3. 六类管理列表采用数据库 count/limit/offset 与最大 ID 快照。历史页固定快照；最新页刷新可见新记录。
   增加每页条数、上一页、下一页、返回最新，以及与不区分大小写查询一致的 SQLite 表达式索引。
4. 房间重命名保留 SIP URI。归档/恢复保留历史；归档要求已连接 ESL、15秒内的完整人数快照与空房间。
   正常房间目录隐藏已归档房间，管理列表仍可查询。新动作抑制重复点击，过期请求不会写回新会话。
5. 日期控件使用浏览器本地时区，包含所选结束当天；API 接收带时区的 fromTime/untilTime，范围为左闭右开。
   话单统计按开始时间计算记录数、完整时长之和及平均时长；全局房间历史峰值单独标注，不随日期筛选变化。
   话单、文件、私聊、群聊 CSV 按同样条件导出所有匹配记录，分批100条，上限10000条。
   超限返回400并要求缩小范围，禁止静默截断。CSV含UTF-8 BOM，正确处理中文、引号、逗号、换行与公式前缀。
6. 运维页显示构建版本/提交、启动时间、运行时长、迁移版本和ESL连接/断开/快照时间及脱敏原因。
   数据库持久化创建账号、禁用/恢复、创建/重命名/归档/恢复房间、管理员登录/退出、导出和拒绝请求的元数据。
   成功的数据变更与操作记录在同一事务；审计写入失败时数据变更回滚。不记录密码、token、ESL口令或聊天正文。

## 接口

全部新增接口位于 `/api/admin/workbench/**`，仅管理员 1001 可访问。

| 接口 | 作用 |
|---|---|
| `GET /{resource}/page` | resource 为 cdr/files/messages/room-messages/users/rooms；返回 items/page/size/total/hasNext/snapshotMaxId |
| `PATCH /users/{id}/state` | `{disabled: true或false, reason: 可选}` |
| `PATCH /rooms/{id}/state` | `{name: 可选, archived: 可选布尔值}`；不修改 SIP URI |
| `GET /query-stats` | 所选范围话单统计，支持 caller/callee/fromTime/untilTime |
| `GET /{resource}/export` | cdr/files/messages/room-messages CSV，鉴权在各批次再次检查 |
| `GET /operations` | 管理员运行状态，敏感连接口令不返回 |
| `GET /audit/page` | 操作记录分页，支持 actor/action/result 与日期范围 |

日期字符串示例：`2026-11-06T00:00:00+08:00`。size 为1–100，page从0开始；首次获取snapshotMaxId后，翻阅历史页继续携带。
现有桌面客户端的资料、房间目录、文件与聊天协议不改变返回结构；仅增加管理接口和可忽略的元数据字段。

## 数据升级与恢复

`SchemaMigration` 在 Hibernate 初始化前执行幂等 SQLite 迁移，记录 schema_versions，给旧 users/rooms
增加禁用/归档字段及默认正常值，建立操作记录和身份保留表。已有密码哈希和业务记录不重写。
索引在表准备完成后创建，重复启动安全。

历史数据只保存用户名而没有不可变用户ID时，无法从现有记录可靠判断过去是否发生过同名身份复用。
本次保留现有历史身份，不自动认领或改写旧记录；部署前应核查已知的历史账号归属。

部署流程：

1. 在短暂的业务后台停写窗口停止旧后台；信令/MCU由协作者维护，保持其原部署安排。
2. 备份数据库及同一数据目录下的上传文件、头像和配置，记录旧程序版本及文件哈希。SQLite文件存在WAL时一并保留。
3. 先在备份副本运行候选包，核对账号ID、密码哈希、历史条数与附件字节；再按原数据路径升级。
4. 升级后核查管理登录、旧客户端登录、分页/导出、禁用/恢复，以及真实ESL状态。
5. 若回滚，先停止候选后台，另外保留升级后的完整数据，然后恢复升级前的数据库、附件与对应旧程序。
   附件索引可能包含路径，恢复时保持原路径布局。不要仅替换旧JAR而继续使用已经升级的新数据。

复现实验：

```powershell
python scripts/verify-admin-upgrade.py --baseline <旧后台包目录> --candidate <新后台包目录> --output <不存在的隔离验证目录>
```

脚本只在新建目录创建本机随机端口的测试后台，ESL关闭；从旧版生成话单、私聊和附件，验证新包迁移、
历史身份保留、禁用/恢复、CSV与审计重启持久化，再在原测试路径恢复旧库与旧程序验证读取，保留升级后数据副本。
只结束脚本自己启动的进程，不访问协作者服务。输出 result.json 及独立 stdout/stderr。

## 功能边界

禁用只控制业务后台权限与目录展示，不立即撤销Kamailio注册或终止已有SIP通话。
房间归档只控制业务目录，不锁定MCU房间或踢除成员；手动SIP拨号的准入需要信令侧另行配合。
所有管理操作均由服务端鉴权，不能仅依靠页面隐藏按钮。
