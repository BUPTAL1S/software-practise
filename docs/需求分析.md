# 需求分析

需求来自课设范围和当前仓库已实现的行为。方法：范围界定、MoSCoW 优先级、用例、ISO/IEC 25010 里与本系统相关的质量属性、需求追踪。图见 [UML.md](UML.md)，使用者见 [用户分析.md](用户分析.md)。

状态分两种：**已实现**（阶段 1–5，代码在 `main`）、**明确不做**（Won't）。阶段 6 只剩双机彩排和打包。

## 问题与目标

两台电脑上的 Java 程序要能互相通话，并能发文字和文件；老师要能在管理页看到通话记录。6–8 人的视频房间需要会议焦点，一对一不能为了房间去绕 MCU。

目标：

- 一对一注册、语音、视频、挂断可靠。
- 文字只交给在线用户；文件走 HTTP。
- 通话结束后能查到时长和简单统计。
- 房间 INVITE 进入 FreeSWITCH 混流；房间不提供群聊。

## 范围

**范围内**

- Windows 与 macOS 共用的 JavaFX 客户端。
- Kamailio：REGISTER、位置查找、一对一转发、MESSAGE、对话内 BYE/ACK。
- 后台：用户、登录、文件、CDR、统计页。
- FreeSWITCH：`room-*` 的 INVITE 进入 `video-mcu-3x3`；ESL 把该房间人数写回 SQLite。

**范围外（明确不做）**

- 自助注册、SIP 与 HTTP 密码同步、离线消息、MSRP。
- 把一对一呼叫送进会议室。
- 技能组、队列、IVR、呼叫中心、Redis、对象存储。
- 用 WebRTC 或网页代替通话客户端。
- 后台主动 `originate` 呼叫。

## 功能性需求

优先级：Must 验收必须有；Should 已做但不增加新架构；Could 可做可不做；Won't 这次不做。

|---|---|---|---|---|

| FR-20 | SIP 密码与 HTTP 密码同步 | Won't | 不做 | 两套密码独立 |

## 用例规约

用例图见 [UML.md](UML.md)。下面写出验收时会走到的主用例。

### UC-01 注册

- 参与者：通话用户、Kamailio；后台登录是附带步骤。
- 前置：引擎已启动，域为 `lab`，传输为 TCP。
- 主成功：发送 REGISTER，收到 200。后台可达时用与用户名相同的密码换 token。
- 扩展：5060 被占用则改用 5062 再注册。本机把校园网 IP 填进 SIP 服务器时，注册超时。

### UC-02 一对一呼叫

- 参与者：主叫、被叫、Kamailio。
- 前置：双方都已注册，且不是同一个账号。
- 主成功：INVITE 到达被叫，被叫接听，媒体接通。挂断后双方 DISCONNECTED，并各上报一次 CDR。
- 扩展：被叫不在线则 404。选择语音时视频路数为 0。视频库缺失时不允许发起视频呼叫。

### UC-03 发送文字

- 前置：主叫已注册。
- 主成功：MESSAGE 原样到达在线被叫，主叫收到 200，界面记为已送达。
- 扩展：被叫不在线为 404。连续多条相同正文按先发送先确认匹配，避免回执串条。

### UC-04 发送文件

- 参与者：发送方、接收方、后台。Kamailio 只转发那条 MESSAGE。
- 主成功：上传得到 `id` 和 `url`，再把 `[FILE] ...` 发给对方；对方下载或预览。
- 扩展：无文件为 400。token 无效为 401。

### UC-05 查看统计

- 参与者：查询者、后台。
- 主成功：打开 `http://localhost:8080/`，看到次数、总时长、平均时长、房间人数峰值和记录列表。
- 业务规则：当前人数来自 ESL，按房间写在 `memberCount`。统计页的 `peakRoomMembers` 取「各房间当前人数的最大值」和「按 CDR 时间重叠扫出来的峰值」里更大的那个。`GET /api/rooms` 里的 `peakMembers` 只按该房间的 CDR 重叠计算。无 Call-ID 时，仅当主被叫相同且开始时间落在约 3 秒内、且新呼叫没有晚于上一通结束，才当成重复上报。

### UC-06 加入房间

- 参与者：通话用户、Kamailio、FreeSWITCH、后台。
- 前置：FreeSWITCH 以 compose profile `mcu` 启动；后台 ESL 已连上 `127.0.0.1:8021`。
- 主成功：INVITE `sip:room-<id>@lab`。Kamailio 把下一跳改成 `sip:freeswitch:5080`，不查位置表。FreeSWITCH 拨号计划 `^(room-.*)$` 进入 `video-mcu-3x3`。每人只收一路合成画面，视频为 `97 H264/90000`、`profile-level-id=42e01e`、`packetization-mode=1`，端口在 UDP `21000-21099`。其他电脑的 SDP 地址是校园网 IP。跑着 Docker 的这台机器，发出去的会议地址被改成 Docker 网关，回来的会议地址被改成 `127.0.0.1`。ESL 用该会议的 `Conference-Size` 更新这一间的人数。
- 扩展：满 8 人后，下一个人会先收到 200，随后会议室判定已满、播放满员提示并结束这一路，人数不增加。向房间发 MESSAGE 得到 `405 Room has no chat`。一对一文字仍发给用户，不发给房间。一对一 INVITE 不进入这条路径，SDP 也不改。

## 质量需求

按质量属性写可检查的说法，不写无法测量的「高可用」。

| 属性 | 要求 |
|---|---|
| 功能适合性 | 一对一与房间路径分离；一对一失败不得自动改打 MCU |
| 性能 | 验收规模是两台电脑、最多 8 路房间视频。瓶颈在混流 CPU 和每路 RTP，不在四张业务表 |
| 可靠性 | Kamailio 重启后注册丢失，用户重新登录即可。SQLite 只跑一个后台进程 |
| 兼容性 | 同一份 Java 跑在 Windows x64 与 macOS arm64；原生库按操作系统加载，不进 git |
| 安全性 | 演示级。HTTP 用内存 token，重启失效。SIP 阶段不鉴权。ESL 有口令，后台不得用它发呼叫 |
| 可维护性 | 三角色只通过域、账号、房间 URI、HTTP 字段、ESL 密码协作 |
| 可移植性 | 信令用 Docker；不依赖主机网络模式 |

传输约束：这套 Windows Docker 上的 Kamailio，客户端必须用 TCP。UDP 会超时。房间媒体另要放行 UDP `21000-21099`。只放行 `5060` 时，人能进房间，其他电脑看不到画面。

## 数据需求

| 实体 | 要记住的事实 | 存在哪里 |
|---|---|---|
| 在线绑定 | 用户当前 Contact、传输和端口 | Kamailio 内存，重启即失 |
| 用户 | 用户名、口令哈希、sipId | SQLite `users`，预置 1001–1008 |
| 文件 | 谁发给谁、路径、大小、时间 | SQLite `files`，字节在 `admin/uploads/` |
| 通话记录 | Call-ID、主叫、被叫或房间、开始时间、时长 | SQLite `cdr` |
| 房间 | 名称、`room-<id>`、上限 8、当前人数 | SQLite `rooms`。当前人数来自 ESL，按房间写回 |

业务库不保存 SIP 注册。文件二进制不进 SIP 报文。

## 接口需求

| 接口 | 要求 |
|---|---|
| SIP | 域 `lab`，用户 `sip:<id>@lab`，代理端口 5060 |
| 房间 URI | `sip:room-<id>@lab`，id 以后台房间标识为准 |
| 登录 | `POST /api/login`，JSON `username`、`password` |
| 文件 | `POST /api/files` 字段 `file`、`from`、`to`；`GET /api/files/{id}` |
| CDR | `POST /api/cdr`；`GET /api/cdr`；`GET /api/cdr/stats` |
| 房间 | `GET /api/rooms`；`POST /api/rooms` 返回 `room-<id>`；`GET /api/rooms/{id 或 sipUri}` |
| ESL | `127.0.0.1:8021`，密码 `ClueCon`；事件 `CHANNEL_CREATE`、`CHANNEL_DESTROY`、`conference::maintenance` |
| 房间媒体 | UDP `21000-21099`。其他电脑对校园网 IP；本机对 `127.0.0.1` |

本机与对端的 SIP 服务器地址不同，这是部署输入，不是第二套接口。

## 假设与约束

- 验收时只有一套信令，跑在一台机器的 Docker 里。
- 校园网地址会随网络变化，由启动脚本探测，不写进 git。
- 演示用户少于 10 个，不为此引入 MySQL。
- 统计页上的当前人数以 ESL 写回的 `memberCount` 为准。峰值还会对照 CDR 时间重叠，两者取较大值。
- 房间没有群聊。在房间里发文字会得到 405；一对一文字仍然发给用户。
